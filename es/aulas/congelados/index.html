Lección 3 · 20 min

Tests congelados y guardia de diff en los tests

Si el agente puede tocar al juez, el juez no vale. Congelar los tests es escribirlos antes, guardar una copia de ellos fuera del alcance del agente y reprobar cualquier cambio. En esta clase ves que proteger solo la carpeta tests/ no basta: un conftest.py en la raíz omite todo y pytest sale con 0.

Comenzar la clase

En esta clase vas a

  1. 1Qué es "el juez": los tests, conftest.py en cualquier nivel y la config de pytest
  2. 2Manifiesto con hash y mínimo de tests, guardado fuera del repo
  3. 3Las cinco reprobaciones: borrado, modificado, nuevo, pocos, omitido
  4. 4El hueco del conftest en el loop headless y la corrección

Objetivo: congelar el juez (tests, conftest, config) con hash y mínimo de tests fuera del repo y reprobar borrar, omitir o modificar.

02 · Ensayo: tres agentes contra la guardia

Congela antes de cada agente y verifica después. GUARDA_DIR queda fuera del proyecto.

Terminal · apaga, conftest y bom
K=~/projetos/loop-r-eng-verificacao-v72/kit
export GUARDA_DIR=/tmp/ensaio-verif/guarda       # fuera del repo
for modo in apaga conftest bom; do
  bash $K/ensaio.sh > /dev/null && cd /tmp/ensaio-verif/proj
  python3 $K/guarda-testes.py congelar .          # ANTES del agente
  $K/agente-falso.sh $modo < /dev/null > /dev/null
  echo "## $modo"; python3 $K/guarda-testes.py conferir .; echo "saída: $?"
done

Si ejecutas congelar después de que el agente ya creó el conftest.py, entra en el manifiesto como si fuera del proyecto y la línea NOVO desaparece. Congela en el commit base, antes del primer ciclo. La guardia aún reprobaría por PULADO, pero pierdes la señal más clara.

03 · El agujero del conftest en el loop headless

El loop-longrun.sh del curso 2 revierte lo que el agente toca en PROTEGIDOS. Con el PROTEGIDOS de ejemplo ("tests/ pytest.ini"), un conftest.py en la raíz pasa y el test final "pasa" sin que se ejecute ningún test. Ensayo con agente falso, sin costo.

Terminal · el agujero (PROTEGIDOS de ejemplo)
K=~/projetos/loop-r-eng-verificacao-v72/kit; L=~/projetos/execucao-longa/tools
bash $K/ensaio.sh > /dev/null && cd /tmp/ensaio-verif/proj
printf '#!/usr/bin/env bash\nexec %s/agente-falso.sh conftest\n' $K > /tmp/agente-conftest.sh
chmod +x /tmp/agente-conftest.sh
$L/novo-longrun.sh $PWD slug > /dev/null && D=$(ls -d $PWD/longrun/*)
echo "Implemente slug() em slug.py. Não mexa em tests/." > $D/prompt.md
cat > $D/loop.env <<'ENV'
TESTE_RAPIDO="python3 -m pytest -q"
TESTE_FINAL="python3 -m pytest -q"
PROTEGIDOS="tests/ pytest.ini"
PERMITIDOS="slug.py"
MAX_CICLOS=3
MIN_CICLO=2
MEM=1G
ESTAGNACAO=3
ENV
git add -A && git commit -qm "longrun: pasta"
CODEX_BIN=/tmp/agente-conftest.sh $L/loop-longrun.sh $D; echo "saída: $?"
Terminal · la corrección (conftest protegido + guardia como test final)
bash $K/ensaio.sh > /dev/null && cd /tmp/ensaio-verif/proj        # recomeça do zero
export GUARDA_DIR=/tmp/ensaio-verif/guarda
python3 $K/guarda-testes.py congelar . > /dev/null
$L/novo-longrun.sh $PWD slug > /dev/null && D=$(ls -d $PWD/longrun/*)
echo "Implemente slug() em slug.py. Não mexa em tests/." > $D/prompt.md
cat > $D/loop.env <<ENV
TESTE_RAPIDO="python3 -m pytest -q"
TESTE_FINAL="GUARDA_DIR=$GUARDA_DIR python3 $K/guarda-testes.py conferir ."
PROTEGIDOS="tests/ pytest.ini *conftest.py"
PERMITIDOS="slug.py"
MAX_CICLOS=3
MIN_CICLO=2
MEM=1G
ESTAGNACAO=3
ENV
git add -A && git commit -qm "longrun: pasta"
CODEX_BIN=/tmp/agente-conftest.sh $L/loop-longrun.sh $D; echo "saída: $?"
ls conftest.py; grep -c "revertido pelo loop" $D/failures.md

error: pathspec 'conftest.py' did not match any file(s) known to git
2026-10-19 04:38:49 ciclo 1: checkpoint commitado
(… ciclos 2 e 3 iguais …)
2026-10-19 04:38:50 PARADO: 3 ciclos sem avanço mensurável — ver failures.md
saída: 2
ls: cannot access 'conftest.py': No such file or directory
3

"teste final passou ()": los paréntesis vacíos son el conteo de passed, que no existe. En la corrección, la línea error: pathspec es inofensiva: el git checkout no conoce el archivo nuevo y el git clean justo después lo elimina.

El loop-longrun.sh (kit execucao-longa, 18/10/2026) decide "terminado" por el código de salida del TESTE_FINAL. pytest sale con 0 cuando todos los tests se saltan, y el conftest.py en la raíz no estaba en PROTEGIDOS. Dos cerrojos lo resuelven: proteger *conftest.py (y la config de pytest que tenga el proyecto) y usar un TESTE_FINAL que exija el mínimo de passed sin saltados, como el guarda-testes.py conferir.

E9 · Guardia en tu proyecto

15 min

En un proyecto tuyo con pytest, congela en el commit base y verifica. Si el proyecto usa otro archivo de config de pytest, ponlo en PROTEGIDOS.

Listo cuando: python3 $K/guarda-testes.py congelar . imprime congelado: N arquivos protegidos, mínimo de M testes con M igual al total de tests, y python3 $K/guarda-testes.py conferir .; echo $? → GUARDA: OK y 0.

06 · En tres frases

El juez es más grande que tests/conftest.py en cualquier nivel y la config de pytest también deciden qué se ejecuta.
Foto fuera de su alcanceHash y mínimo de tests guardados antes del agente, en un lugar donde él no escribe.
