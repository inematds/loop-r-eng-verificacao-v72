Lección 2 · 18 min

Comando → salida: verificar el criterio y el evaluador del /goal

Un criterio solo vale si alguien de afuera puede comprobarlo sin confiar en el agente. En esta clase ejecutas cada criterio del goal.md como comando, ves cuál de ellos pasa por atajo y aprendes dónde debe aparecer la prueba: el evaluador del /goal en Claude Code solo lee la conversación.

Comenzar la clase

En esta clase vas a

  1. 1El formato comando → salida y los tres tipos de salida esperada
  2. 2conferir-goal.py: OK o FALHOU por criterio, con código de salida
  3. 3Criterio sin comando y criterio que pasa por atajo
  4. 4Qué ve el evaluador del /goal y qué no ve

Objetivo: comprobar cada criterio del goal.md por comando, ver qué nivel 2 pasa por atajo y poner la prueba en la conversación que lee el evaluador del /goal.

01 · Del criterio a la prueba en la conversación

Haz clic en cada etapa.

FALTAM N: el agente continúa en el siguiente turno
Haz clic en cada bloque del diagrama para ver qué hace.

Un comando que tú ejecutas y una salida que aparece: es la misma prueba para ti, para el loop headless y para el evaluador del /goal.

02 · El goal.md del ensayo

Seis criterios. Uno no tiene comando y otro pasa por un atajo. Encuentra los dos antes de ejecutar.

kit/goal-ensaio.md (criterios; traducción para leer; el archivo del kit está en portugués)
## Criterios de terminado
**Función**
- [ ] `python3 -m pytest -q tests/` → `3 passed`
- [ ] `python3 -c "from slug import slug; print(slug('Ação & Reação!'))"` → `acao-reacao`

**Regresión**
- [ ] `python3 -m pytest -q tests/ -rs` → `código 0`

**Límite**
- [ ] `git diff --stat HEAD -- tests/ pytest.ini` → `vazio`
- [ ] `git ls-files --others --exclude-standard -- '*conftest.py' tests/` → `vazio`
- [ ] o código fica limpo e bem documentado
Terminal · antes, atajo y después
K=~/projetos/loop-r-eng-verificacao-v72/kit
bash $K/ensaio.sh > /dev/null && cd /tmp/ensaio-verif/proj
cp $K/goal-ensaio.md ../goal.md            # fuera del proyecto: el agente no edita el criterio

python3 $K/conferir-goal.py ../goal.md; echo "saída: $?"     # A) antes del trabajo: tiene que fallar

$K/agente-falso.sh conftest < /dev/null                       # B) atajo: salta los tests
python3 $K/conferir-goal.py ../goal.md; echo "saída: $?"

rm conftest.py && $K/agente-falso.sh bom < /dev/null           # C) trabajo correcto
sed -i '/limpo e bem documentado/d' ../goal.md                 #    y el criterio sin comando sale
python3 $K/conferir-goal.py ../goal.md; echo "saída: $?"

El comando aparece cortado a 60 caracteres en la salida. En la ronda B, código 0 dio OK con los tres tests saltados: es el criterio de nivel 2 del goal.md.

Si la ronda A (antes de cualquier trabajo) ya da OK en un criterio de función, el criterio no mide el trabajo. Todo criterio de función tiene que fallar antes; los de límite (nada modificado) pueden pasar desde el inicio.

03 · La condición del /goal con prueba

Como el evaluador solo lee la conversación, la condición exige la salida pegada. En los prompts de goal del kit execucao-longa y del kit 15 comandos el patrón es el mismo.

06 · En tres frases

VerificableUn criterio sin comando no se verifica; conferir-goal.py lo cuenta como FALHOU.
Falla antesUn criterio de función que ya pasa antes del trabajo no mide nada; "código 0" solo pasa incluso con todo omitido.
Prueba impresaEl evaluador del /goal solo lee la conversación: la condición exige la salida pegada terminando en PRONTO.
