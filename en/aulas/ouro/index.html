Lesson 5 · 20 min

Golden set: evals for your agent

You changed the prompt, swapped the model, installed a skill: did the agent get better or just different? A golden set is a frozen list of real cases with the right answer, checked by code, that you run on every change. In this lesson you build one, compare two versions, and see a regression hidden behind the same total.

Start the lesson

In this lesson you will

  1. 1The case format: id, category, input, expected, source
  2. 2The three kinds of grader: code, model, and person
  3. 3Scoreboard by category and case-by-case regression
  4. 4When the set got too easy

Goal: build a golden set with real cases, grading by code, and a comparison with the previous version that flags regressions.

02 · Rules for a golden set

From the sources: Anthropic (agent evals), LOOP-R and the FEC track.

1. Three graders

By code (tests, static analysis, checking tool calls), by model (rubric, pairwise comparison, multiple judges) and by person.

The model-based grader has to be calibrated with human labels before it counts.

2. Size

LOOP-R asks for 20 to 50 cases per artifact eval and treats fewer than 30 observations as a weak signal.

The rehearsal uses 10 cases to fit on the screen; yours starts with 20.

3. Freeze with a date

The FEC track's set has a set id, a freeze date, and for each case: id, question, expected facts and category.

In the 05/02/2026 version it announces 30 cases and has 3 filled in: a good structure is not a finished set. Count the lines before trusting the score.

03 · The set and the rehearsal agent

An issue triage agent: it returns the type (bug, request, question) and whether it is urgent. The 10 cases are examples written for the course.

kit/evals/casos.jsonl (3 of 10 lines; translation for reading; the file in the kit is in Portuguese)
{"id": "t01", "categoria": "bug", "entrada": "After yesterday's deploy, login returns a 500 error for all users.", "espera": {"tipo": "bug", "urgente": true}, "origem": "course example"}
{"id": "t06", "categoria": "pedido", "entrada": "Can you add PDF export?", "espera": {"tipo": "pedido", "urgente": false}, "origem": "course example"}
{"id": "t07", "categoria": "armadilha", "entrada": "The system doesn't work the way I expected: where is the dark mode option?", "espera": {"tipo": "duvida", "urgente": false}, "origem": "course example: looks like a bug, is a question"}
kit/evals/prompt-triagem.md (translation for reading; the file in the kit is in Portuguese)
You triage issues for a web system. Read the issue at the end and classify it.

tipo: "bug" (something broken), "pedido" (new feature) or "duvida" (usage question).
urgente: true only if the system is down, money or data is being lost, or there is a security flaw.

Answer with a single line of JSON only, nothing else:
{"tipo": "bug", "urgente": false}

Both versions score 9/10. Version 2 fixed the trap (t07) and broke a request (t06, which ends in "?" and turned into a question). The total alone would say "tie".

An aggregate score hides a swap: one case gets better, another gets worse, and the number stays the same. Compare case by case with the previous version and treat any regression as a block, even when the total goes up.

Claude Code 2.1.303, the subscription's default model, 1 min 19 s for the 10 cases. The model's score may change on your machine; the file with 11 lines (header + 10) will not.

A set that the agent gets entirely right does not separate the good version from the bad one: any change will score 100%. When that happens, add harder cases (the real traps, the ambiguous inputs) until the score has room to be wrong again.

E15 · Your agent's golden set

40 min

Choose an agent or prompt of your own with output you can check. Write 20 cases in the casos.jsonl format, starting with the failures you have already seen, and a prompt that asks for JSON. Run the current version as a baseline.

Done when: wc -l < [your cases].jsonl → 20 or more, and python3 $E/rodar-evals.py --agente "[your agent]" --casos [your cases].jsonl --prompt [your prompt] --saida base.tsv prints the total line with less than 100%.

07 · In three sentences

Real cases, frozenOne JSON line per case, with the expected result and origin; changing a case means a new version of the ruler.
Code gradesAsk for JSON and check it field by field; use a model judge only for the subjective.
Regression blocksCompare case by case with the previous version; an equal total can hide a swap.
