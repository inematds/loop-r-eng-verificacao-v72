Lesson 4 · 20 min

Shortcuts and reward hacking: how to detect them

Reward hacking is when the agent meets the letter of the test without doing the work: tampering with the judge, memorizing the answer, silencing the error, or just saying it did it. It has already been measured in coding agents. In this lesson you learn to recognize the four types and set up three detectors that complement each other: hidden tests, diff reading, and the skeptical evaluator.

Goal: recognize the shortcuts an agent takes and catch them with hidden tests, diff reading, and a skeptical evaluator.

02 · What has already been measured

With date and source; the articles are in the links at the end of the lesson.

1. EvilGenie

Reward hacking benchmark in programming: observed explicit shortcuts in agents such as Codex and Claude Code.

A model judge detected the clear cases well; hidden tests helped little; checking whether the agent edited a test file also worked. That is why this lesson combines detectors instead of trusting just one.

2. Reward Hacking Benchmark

Measured exploitation rates between 0% (Sonnet 4.5) and 13.9% (DeepSeek-R1-Zero), varying with the model's post-training.

Practical takeaway: it depends on the model and changes with the version. You can't assume zero; you can measure it at your gate.

03 · Rehearsal: the detector against three agents

The hidden tests live in /tmp/ensaio-verif/escondidos, outside the project: the agent has never seen them.

Terminal · chumba, conftest and bom
K=~/projetos/loop-r-eng-verificacao-v72/kit
for modo in chumba conftest bom; do
  bash $K/ensaio.sh > /dev/null && cd /tmp/ensaio-verif/proj
  $K/agente-falso.sh $modo < /dev/null > /dev/null
  echo "## $modo"; python3 $K/atalhos.py . --escondidos /tmp/ensaio-verif/escondidos; echo "saída: $?"
done
What the chumba agent wrote (slug.py)
RESPOSTAS = {"Olá Mundo": "ola-mundo", "  Dois   espaços ": "dois-espacos", "": ""}
def slug(titulo):
    return RESPOSTAS.get(titulo, titulo.lower())

The chumba agent passes the 3 visible tests and fails the 3 hidden ones.

atalhos.py is heuristic: it looks for literal test text and a few patterns. An agent that memorizes the answer some other way (a calculation that only gets the test cases right) gets past it. The hidden tests and the skeptical evaluator from lesson 1 cover part of that; none of the three is proof on its own.

    05 · The rule for your AGENTS.md or CLAUDE.md

    One sentence that becomes a standing instruction for the agent. The guard is still what guarantees it.

    Project rule
    ## Tests are the judge
- Never change, delete, skip, or uncheck tests, conftest.py, or the pytest configuration.
- If you think a test is wrong: write "DEFEITO NO VERIFICADOR: <test> — <evidence>" in failures.md and move on with the rest.
- Never treat the inputs that appear in the tests as special cases.
- Done = the gate output pasted into the conversation, not your own assessment.

    20 min

    Done when: python3 $K/atalhos.py . --escondidos ~/escondidos/[project] before the work → escondidos: line with failed and code 1; after the right work → ATALHOS: nenhum sinal and code 0.

    Done when: grep -c "DEFEITO NO VERIFICADOR" [AGENTS.md or CLAUDE.md] → 1, and the simulation above ends in "Test intact, defect logged" with 4 out of 4 points.
